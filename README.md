# 函数战争 · Graphwar 中文复刻版

> 参考仓库：<https://github.com/catabriga/graphwar>（Java 原版）
> 本项目用纯前端（HTML5 Canvas + 原生 JavaScript）完整复刻其玩法内核，界面全中文、主配色为绿色，并内置分步中文新手教程。

## 一、这是什么

一款**回合制数学炮术对战游戏**。你手中的武器是一条**函数表达式**——它会被翻译成从士兵脚下射出的真实飞行轨迹。
越过起伏的山体、绕开身边的战友、命中敌方的阵地，这就是全部目标。

两种开炮方式，屏幕**最上方**始终显示刚刚操作的那条函数：

- **写函数**（底部横幅）：直接输入表达式，例如 `-((x+16)*(x-14))/20`，顶部显示原式；
- **画函数**（战场左侧画板）：按住拖出一笔，**这一笔只决定方向，不决定长度**——
  系统会把它最小二乘拟合成一条多项式曲线（例如 `y = -0.034*x^2 + 1.42*x - 2.1`），
  然后像普通函数一样**无限延长**飞出去，直到撞到地形、击中士兵或飞出战场。
  顶部显示的同样是这个拟合出来的**函数数值**，而不是「手绘」二字。
  画完还能用「方向 / 大小」两个滑块旋转与缩放，函数式与弹道预览都会实时变化。

三种弹道规则（与原作一一对应）：

| 模式 | 你要输入 | 弹道 |
| --- | --- | --- |
| 普通函数 | `y = f(x)` | 函数图像本身；系统自动加常数平移到士兵脚下 |
| 一阶微分方程 | `y' = f(x, y)` | 以士兵位置为初值，四阶龙格—库塔法数值求解 |
| 二阶微分方程 | `y'' = f(x, y, y')` | 初值为士兵位置 + **发射角**（↑/↓ 调整） |

再选<b>开一局的形式</b>（主菜单 → **开始对战**）：

- **双人对战（同屏轮流）**——你和朋友共用一台设备轮流操作；
- **人机对战（电脑执子）**——你先手，其余回合交给电脑；
- **多人模式（多队对抗）**——先设 <b>队伍总数</b>（2 / 3 / 4 队）与 <b>每队人数</b>（1 / 2 / 3 / 4 人），
  两者相乘就是总人数（上限 8 人）：2 队 × 2 人 = **2v2 四人局**、2 队 × 3 人 = **3v3 六人局**、
  2 队 × 4 人 = **4v4 八人局**、3 队或 4 队则是多队混战（人人一队时徽章显示 `1v1v1`）。
  超过 2 人时每人只指挥 1 名士兵，进入战场前**每个玩家各选一次技能**；
- **联机对战**——见下方「方式 4」。

## 二、启动方式（任选其一，无需安装任何依赖）

### 方式 1：直接双击

双击根目录下的 **`index.html`**，用 Chrome / Edge / Firefox 打开即可开玩。
（全部资源都是本地相对路径，不需要联网，也不需要构建。）

### 方式 2：本地静态服务器（推荐，避免个别浏览器的本地文件限制）

在项目根目录执行任意一条：

```bash
# 已装 Python
python -m http.server 8080

# 或已装 Node
npx serve .
```

然后浏览器访问 <http://localhost:8080>。

### 方式 3：联机对战（在线房间，零依赖）

启动一个内置的零依赖 Node 服务器（仅用 Node 内置模块，无需 `npm install`），它同时承担了
「静态站点托管」与「WebSocket 房间 + 权威对局」两项职责：

```bash
# 在项目根目录执行，默认监听 8080 端口（可用 PORT 环境变量改端口）
node server/server.js

# 可选：换端口
PORT=9000 node server/server.js
```

启动后在**同一台机器**用浏览器打开 <http://localhost:8080>；若要让**同局域网**的其他设备加入，
把地址里的 `localhost` 换成这台机器的局域网 IP（如 `http://192.168.1.20:8080`）。
（公网游玩需把服务器跑在有公网 IP 的机器 / 云主机上，并放行对应端口的 TCP 入站。）

进游戏后点主菜单的 **「联机对战」**，流程如下：

1. 一方选「普通函数 / 一阶 / 二阶」、每方士兵数，要多人就选**多人赛制：队伍总数 × 每队人数**（如 2 队 × 3 人 = 3v3 共 6 人），
   点 **创建房间** → 得到 4 位房号（如 `K7P2`）；
   服务器会**自动探测本机公网 / 局域网 IP**，并生成一条可直接复制的**一键加入链接**
   （形如 `http://<IP>:8080/?room=K7P2`）——发链接给朋友，他**点开即自动进入大厅并加入房间**，
   无需手动填服务器地址、也无需手动输房号（不必知道自己的 IP）；
2. （朋友侧）也可以走传统方式：在「房号」框填入房号，点 **加入房间**；
3. 两人都进入后，服务器**生成同一张地图**并随机决定先手，**两端同时开打**；
4. 轮到你时界面才会亮起，开炮（写函数 / 画函数 / 调发射角）后把「开炮意图」发给服务器，
   由服务器**统一计算弹道并广播**给双方，两人看到的是同一颗炮弹、同一处爆炸；
5. 一方全灭即分胜负，可点 **再来一局** 重开（同一房号、新地图）。

> **对局内互动**：顶部「**快捷语**」按钮可一键发送预设语句（催一催、打得好、手滑了、GG…），
> 对手会看到气泡提示。语句由服务器**按白名单 id 转发**，无法发送任意文本，杜绝骚扰。
>
> 说明：联机模式与原有的「同屏双人（轮流）」「人机」完全并存，主菜单三选一即可。
> 大厅里「服务器地址」默认填「当前打开页面的主机」，一般不用改；创建房间后，页面会直接把
> 带公网 / 局域网 IP 的加入链接准备好，复制即可。
> 单玩练习：创建房间时勾选「**人机补齐**」，没有真人对手时服务器直接以 AI 为对手立即开局；
> 对局中对手若掉线，AI 也会**接管其阵地**继续，不必重新开局。

### 方式 4：点对点联机（不用服务器，房主的浏览器就是服务器）

不想 / 不能开服务器时，用大厅里的 **「点对点联机」**：两台设备经 **WebRTC 数据通道直连**，
**房主的浏览器承担权威对局端**（等价于上面的服务器），对局数据不经过任何第三方。

握手只需来回复制**一次**连接码：

| 步骤 | 房主 | 朋友 |
|---|---|---|
| ① | 点 **「我是房主：生成邀请码」**，复制那串码发给朋友 | 把邀请码粘贴到「对方的连接码」，点 **「我加入：贴邀请码生成回执码」** |
| ② | 把朋友发回的「回执码」粘贴到「对方的连接码」，点 **「贴回执码 → 开始对战」** | 复制生成的「回执码」发回给房主 |
| ③ | 直连建立 → 自动生成战场并开局（顶部徽章显示「联机（房主）」） | 自动进入同一张地图，双方开打 |

> - 之后所有对局数据都走点对点通道，**不再需要任何服务器**，也支持「再来一局」（同一条直连、新地图）。
> - 页面必须是 **`https://` 或 `localhost`**——这是浏览器对 WebRTC 的硬性要求；
>   用局域网 IP 以 `http://` 打开的页面会被禁用点对点（此时请回到「方式 4 服务器联机」）。
> - 连接靠公共 STUN 穿透家用路由器；**少数网络（对称 NAT、部分校园网 / 企业网）必须 TURN 中转**，
>   本实现不含 TURN，连不上时会明确提示改用服务器联机。
> - 房主关掉页面即视为离开，客人端会收到提示并退出。

```
│   ├── sketch.js       # 手绘画板：同比例画板、多项式最小二乘拟合、方向 / 大小调节

│   └── main.js         # 启动
├── server/             # 联机服务器（零依赖 Node，仅内置模块）

│   └── package.json    #   启动脚本：node server.js
└── README.md
```

## 三点五、界面布局（全屏零滚动）

一屏之内放下所有东西，电脑常规分辨率与手机竖屏都**不需要上下滚动**。
手写函数框已改成**竖屏计算器样式**（四列符号键盘 + 大号发射键），两个次级窗口都能**拖动 + 最小化**，
不想看时可以一键收起，把整块战场露出来：

```
┌──────────────────────────────────────────────────────────┐
│ 顶栏：回合方 · 倒数计时 · 规则/重开/退出                  │
├──────────────────────────────────────────────────────────┤
│ 函数数值条：左军战况 │ 当前弹道指令（大字函数式）│ 右军战况 │
├────────────┬─────────────────────────────────────────────┤
│ 画函数     │                                             │
│ （手绘画板 │            战场坐标平面                     │
│  + 方向    │           （等比缩放居中）                  │
│  + 大小）  │                                             │
├────────────┴─────────────────────────────────────────────┤
│ 写函数：y = [ 输入框 ] [发射] · 符号键盘 · 示例 · 发射角   │
└──────────────────────────────────────────────────────────┘
```

- **顶部**：双方战况（编号牌、得分、命中 / 误伤）+ 中间的大字**函数数值**。
  这里取代了原来的侧边战斗日志；命中、误伤、超时等重要事件改在战场上以短促浮层提示，不再占版面。
- **中部**：左侧画板与战场**同一比例（770 : 450）**、同高度，你在画板上画的方向就是战场上看到的方向；
  右侧战场画布按容器等比缩放居中。
- **底部**：写函数整条横幅（输入框、发射按钮、符号键盘、示例、二阶模式的发射角）。
- **手机端**（宽度 ≤ 900px）自动切换为单列：战场 → 画函数 → 写函数，触控绘制，同样一屏可见。

### 次级窗口（手绘 / 手写）

| 窗口 | 位置 | 操作 |
| --- | --- | --- |
| 手绘函数窗口 | 电脑：战场左侧浮层；手机：贴底抽屉 | 电脑端拖动**顶部把手**可随意摆位；点右上角 **`-`** 最小化（再点标题栏上的标题即可展开） |
| 手写函数窗口（竖屏计算器） | 电脑：战场下方 / 右下浮层；手机：贴底抽屉 | 同上；内部为竖排：动作切换（**攻击 / 位移**）→ 位移距离滑杆 → 三种导弹 → 表达式行 → 四列符号键盘 → 发射键 |

电脑端两个窗口都可拖动（拖出屏幕自动贴边夹住），最小化后只留一条标题，点标题即可还原。

### 手机端适配（宽度 ≤ 760px）

- 两块浮动面板不再叠在战场上，而是变成**贴底的抽屉**，只占 `bottom: 62px` 以下、`max-height: 48vh`，
  战场净空完整保留；
- 战场下方出现一条**底部标签页**：`✎ 画函数` / `⌨ 指令台` / `▾ 让开战场`——
  前两个切换抽屉（同一时刻只展开一个），点「让开战场」则两块面板全部收起，露出整块战场；
- 触控尺寸放大：符号键 `min-height: 42px`、表达式输入框 `font-size: 16px`（避免 iOS 聚焦时页面自动缩放）、
  小按钮 `min-height: 34px`，手指点按不易点错；
- 手写计算器（`funcbar`）**横向滚动**不换行，8 人同屏时也不会把顶部战况挤出屏幕；
- 手机端**禁用拖动**（抽屉本身已固定位置），避免与手势冲突；技能选择弹窗改为**两列网格**，单手也能点。

## 四、核心机制与原作对照

| 机制 | 实现位置 | 说明 |
| --- | --- | --- |
| 表达式解析 | `expression.js` | 沿用原版规则：统一小写、`-` 改写为 `+-`、`exp` 改写为 `e^`、同一条正则切词、省略乘号补全、「括号最浅 + 类型编号最小」优先重排为波兰式、`valuesNeeded` 校验合法性 |
| 常数平移 | `trajectory.js` | 普通函数模式下 `offset = -f(x₀) + y₀`，保证曲线经过士兵脚下，因此写任何常数都不影响结果 |
| 出膛角 | `trajectory.js` | 迭代求解使出膛方向贴合该点切线/斜率（迭代误差 `π/360`，最多 100 次） |
| 数值积分 | `trajectory.js` | 步长 0.01，单步位移超过阈值则对半细分，低于最小步长则认为函数爆炸 |
| 地形 | `terrain.js` | 由若干随机圆构成，像素掩码判定；炮弹终点炸出半径 12 的缺口 |
| 误伤判定 | `trajectory.js` / `game.js` | 逐点与**全部**士兵（含己方队友，仅排除正在开炮者）做半径 7 的距离判定 |
| 回合轮转 | `game.js` | 每回合 2 分钟；命中/落地后延迟 3 秒，轮到下一名**存活**士兵；阵亡者自动跳过 |
| 胜负结算 | `game.js` | 某一阵营士兵全部阵亡即判负；同时全灭为平局 |
| 计分（本作新增） | `game.js` | 命中敌方 +100、误伤己方 −50，胜负仍以「全歼」为准 |
| 血量（本作新增） | `constants.js` / `game.js` | 每名士兵 **100 点血**，炮弹按「路径穿过的士兵持续掉血 + 落点爆炸径向伤害」扣血，只有血量归零才阵亡 |
| 三种导弹（本作新增） | `constants.js` | 发射前可选：**重炮弹**（70 伤、爆炸半径 16）、**标准弹**（40 伤、半径 11）、**散弹**（15 伤 × 5 枚，覆盖面更大） |
| 位移（本作新增） | `game.js` | 每回合可选「位移」代替开炮：沿**同一条函数曲线 / 手绘曲线**前移一小段（默认上限 **5 格**，可拾取「疾行靴」临时 +3），终点撞地形或越界则被拒绝 |
| 开局技能（本作新增） | `game.js` / `ui.js` | 进入战场前**每一位玩家各选一个**技能（逐席轮选、可回退、末席点「确定」统一生效），**每局限一次且消耗本回合**：应急修理（+45 血）／群体维修（己方全队 +30）／火力强化（下一发 ×1.6）／侦察卫星（辅助线 +80px） |
| 随机奖励包（本作新增） | `game.js` | 每回合结束按概率空投补给箱（最多 3 个），**炮弹击中或位移途中碰到**即可拾取：维修包 / 瞄准镜（辅助线 +50）／强化弹头 / 疾行靴 |
| 多人模式 · 队伍总数 × 每队人数（本作新增） | `constants.js` / `game.js` / `terrain.js` / `server.js` | 主菜单选 **「多人模式（多队对抗）」**，里面只填两个数：**队伍总数（2 / 3 / 4 队）** × **每队人数（1 / 2 / 3 / 4 人）**，相乘即总人数（上限 **8**）。<br>于是 2 队×2 人 = **2v2（4 人）**、2 队×3 人 = **3v3（6 人）**、2 队×4 人 = **4v4（8 人）**、3 队×2 人 = **2v2v2（6 人）**、4 队×2 人 = **2v2v2v2（8 人）**、3 队×1 人 = **1v1v1 混战（3 人）**。总人数 &gt; 2 时每人只指挥 1 名士兵，席位名为「第 N 队 · M 号」，打光某一整队即该队判负；徽章显示当前赛制标签 |
| 赛制换算（共用） | `constants.js` | `GW.seatsFromRoster(teams, perTeam)`（赛制→人数）、`GW.rosterFromSeats(n)`（人数→赛制）、`GW.seatTeamIn`、`GW.teamLabel(teams, perTeam)`、`GW.teamQuota`；本地 / 服务器权威 / 点对点房主三条链路调用同一套，越界自动收敛 |
| 每人各选一个技能 | `ui.js` / `game.js` | 进入战场前**每一位玩家（席位）都各自选一个技能**：弹窗逐席轮选，可点「上一位」回退修改、由**最后一个席位点「确定」统一提交**；联机则各席位通过 `skill_pick` 单独上报，人多时技能循环复用 |

> 说明：原版为网络多人房间制。本复刻版早期改为**同一台机器上的双人对战（轮流操作）**与**人机对战**两种形式；
> 自 v3.1 起已重新加回**联机对战（在线房间）**——启动 `node server/server.js` 后，两名玩家可经局域网 / 公网
> 同图对战，弹道由**服务器权威计算**、两端同步回放。三种形式的战斗平面均为同一张共享地图，规则与手感保持一致。

## 五、操作说明

- **写函数**：输入表达式 → 画面出现**虚线预览**与**预瞄准线**（从士兵脚下射出的箭头，方向随函数实时改变）→ 回车或点「发射」开火；
- **画函数**：在左侧画板上按住拖出一笔定方向 → 松手后可用「方向」「大小」微调 → 点「发射手绘弹道」；
  画板上灰虚线是原始笔迹、绿虚线是拟合后**无限延长**的曲线，弹道会一直飞到撞上东西为止；
- 二阶微分方程模式下使用 **↑ / ↓**（或按钮）调整发射角，画布上实时显示角度；
- 每回合限时 **2 分钟**，超时自动跳过；
- 鼠标在画布上移动会显示该点坐标，方便估算敌人所在的 x/y（战场**不显示坐标轴与刻度**，画面更干净）；
- **位移**：把手写框顶部的「攻击 / 位移」切到**位移**，会出现距离滑杆（默认上限 5 格），
  输入表达式或画一笔曲线来**决定移动方向**——士兵会沿这条曲线走一小段，
  途中碰到补给箱顺手捡走；终点如果卡进山体或越界会被拒绝并提示缩短距离。

### 三种导弹与血量

| 导弹 | 伤害 | 爆炸半径 | 特点 |
| --- | --- | --- | --- |
| 重炮弹 | 70 | 16 | 单发高伤，适合精准点名 |
| 标准弹 | 40 | 11 | 均衡，默认选中 |
| 散弹 | 15 × 5 枚 | 9 | 覆盖面广，靠多发溅射吃饭 |

炮弹打过的地方会**沿路径持续扣血**，落点还有一次径向伤害（带衰减），所以「一炮打死」已经不存在了：
想拿人头要么直接轰到脸上，要么用重炮弹 / 强化弹头。士兵头顶的血条就是他的血量。

### 函数书写规则

| 类别 | 可写内容 |
| --- | --- |
| 变量 | `x`、`y`、`y'`（二阶模式还可写 `y''` 左侧，会自动忽略） |
| 运算符 | `+` `-` `*` `/` `^` |
| 函数 | `sqrt()`、`log()`（底 10）、`ln()`、`abs()`、`sin()`、`cos()`、`tan()` |
| 常量与简写 | `e`、`pi`、`exp(x)`；省略乘号（`2x`、`(x+1)(x-1)`、`xsin(x)`）；全角括号、中文符号 `× ÷ − √ π` 自动识别 |
| 常见写法 | `((x-3)^2)/20`、`sin(x/20)*5`、`ln(abs(x))`、`1.04^(-(x+3)^2)*20` |

三个最容易踩的坑（教程第 5 步有详细演示）：

1. **常数无效**：`2*x+3` 与 `2*x-8` 射出的轨迹完全一样；
2. **坐标只有 ±25**：`x^2` 会瞬间冲出天际，请写成 `(x^2)/50` 这类缩放后的形式；
3. **定义域爆炸**：己方永远在左半场（x 为负），`sqrt(x)` 会当场炸掉，应写 `sqrt(abs(x))`。

## 六、新手教程

主菜单 → **新手教程**，共 9 步，采用固定场景逐步讲解：
目标 → 坐标系 → 战况与函数数值条 → 函数写法 → 常数平移 → 开火 → 地形与误伤 → **手绘弹道** → 回合与胜负。
（教程沿用「一人一炮定胜负」的经典教学场景，便于先把函数这件事讲透；正式对局才有血量、导弹、技能与位移。）
其中第 5、6、8 步需要**动手操作**（分别是输入预览、发射、画一笔）后才会继续，
第 5 步给出的示例函数在教程地图上必定命中敌人。

动手步骤会自动**虚化**：不再压暗整个屏幕（只给高亮区加一圈细边框），
教程卡片自动缩窄并**挪到与当前操作区完全不重叠的位置**（上 / 下 / 左 / 右四边自动择优），
随时还能点右上角「收起」把卡片缩成一条标题栏，因此任何一步都不会挡住你要点的东西。

后 4 步（第 10–13 步）讲正式对局的**新玩法**：血量与三种导弹、**位移**（这一回合走而不是打）、
**开局技能与随机空投**（第 12 步明确「**每一个人都要各选一个**，可以回退、最后统一确认」）、
两个可收起的**次级窗口**（手绘 / 手写计算器布局，第 13 步还讲了**手机端底部标签页抽屉**怎么用）。

**人数与赛制**（第 3 步）：对多人局，先选 **队伍总数**（2 / 3 / 4 队）再选 **每队人数**（1 / 2 / 3 / 4 人），
两者相乘就是总人数——**2 队×2 人 = 4 人（2v2）**、**2 队×3 人 = 6 人（3v3）**、**4 队×2 人 = 8 人（2v2v2v2）**、
**3 队×1 人 = 人人一队混战**；徽章上的 `2v2` / `3v3` / `2v2v2` / `1v1v1` 就是当前赛制。

**联机教程**：主菜单 → **联机对战** → 大厅的 **「联机教程」** 按钮，共 8 步，
逐步讲解「连上服务器 → 选模式与人数 → 创建 / 加入房间 → **点对点联机** → 人机补齐 → 对局内怎么打（含快捷语）」，
无需进入战场即可学会整套联机流程。

## 七、上传到 GitHub 与开通 Pages

目标：推到 `ALaaa111/Hanshu` 的 `main` 分支，开通 **分支源** 的 GitHub Pages，
线上地址固定为 `https://alaaa111.github.io/Hanshu/`。仓库根目录已有 `.nojekyll`（跳过 Jekyll）。

仓库里只有游戏本体（`index.html` / `css/` / `js/` / `assets/soldier_sprite.png` / `server/`），
**没有任何脚本、日志或令牌文件**。上传就两种方式，选一个：

### 方式 1：GitHub 网页手动上传（最简单，不用装 git）

1. 打开 <https://github.com/ALaaa111/Hanshu>，进入仓库
2. 点右上角 **「Add file」→「Upload files」**，把下面这些**拖进框里**（仓库本来就在的直接改）：
   - `index.html`、`README.md`、`.nojekyll`、`.gitignore`
   - 整个 `css/`、`js/`、`assets/`、`server/` 四个文件夹（点 **「Add file」→「Create new file」**
     或在本地压成文件夹后上传，更省事的做法是先 `git add -A` 再用方式 2）
3. 拉到页面底部，填 commit 说明（如 `update`），点 **「Commit changes」**
4. 仓库 →【Settings】→【Pages】→ **Source** 选 **「Deploy from a branch」**，
   分支选 `main`、目录选 `/ (root)`，点 **Save**
5. 等 1~2 分钟，访问 <https://alaaa111.github.io/Hanshu/>；看不到样式时确认根目录有 `.nojekyll`

> 手动上传**改一个文件就要再传一次**，之后建议直接用方式 2。

### 方式 2：本地敲三行（git 推一次，以后只推改动）

在自己电脑的项目根目录（装好 git 后）依次执行：

```bash
git add -A
git commit -m "update"
git push origin main
```

推完再去 Pages 那里确认一次构建状态即可。
如果 `git push` 要账号密码，用 **PAT 当密码**：

1. GitHub → 右上角头像 →【Settings】→【Developer settings】→【Personal access tokens】→【Fine-grained tokens】→【Generate new token】
2. **Resource owner**：`ALaaa111`；**Repository**：只勾 `Hanshu`
3. **Permissions**：`Contents: Read and write`；`Pages: Read and write`；其余保持默认
4. 生成后复制；`git push` 时**用户名填 `ALaaa111`，密码就填这个 PAT**
5. 提示后卡住？执行 `git credential-manager github logout` 再推一次重新输

> 旧的那版 PAT 对 `Hanshu` 只有 metadata 权限，写操作会报
> `403 Resource not accessible by personal access token`——必须按上面重新生成一个带 `Contents` 写的。

## 八、已知限制

- **多人（>2 人）需要服务器联机**：点对点直连只支持 **2 人**（房主 + 1 位客人），
  大厅里把赛制调成 2 队以上会自动锁回「2 队 × 1 人」（点对点下其他组合显示为禁用）——
  点对点要建多人网格通道，超出本实现的范围；
  在线房间模式下 **队伍总数 2 / 3 / 4 × 每队人数 1 / 2 / 3 / 4** 均可（上限 8 人），
  `GW.seatsFromRoster` 会把越界组合收敛（例如 4 队 × 4 人 → 4 队 × 2 人 = 8 人）；
  人数多于已知技能数量（4 个）时技能允许重复，保证**每个席位都被问到**、人人各选一次；
- 联机对战已实现「在线房间 + 服务器权威弹道 + 快捷语互动」，
  **服务器权威端同时跑一套与浏览器完全相同的规则**（开炮 / 手绘 / 位移 / 技能 / 奖励包），
  客户端只上报意图、不看结果，因此本地人机、服务器联机、点对点房主三条链路规则一致；
  技能选择走 `skill_pick` 消息（未开炮前可以随时改，用过后不可改）；
  但**未实现**原版的自由聊天指令（`-skip`、`-sayfunc` 等）；无观战、无中途加入；
  对局中一方掉线时由 **AI 接管其阵地**继续，掉线方无法再连回原房间；
- **点对点联机**需浏览器支持 WebRTC 且页面为 `https://` / `localhost`；不含 TURN 中转，
  因此约 10%–20% 的网络（对称 NAT、部分校园网 / 企业网）可能连不通，此时请改用服务器联机；
  连接码只在握手时用一次，之后无需再复制；
- 电脑 AI 采用遗传算法，在「战术核心」难度下仍在约 2 秒内完成一轮搜索，属于「够用但不完美」的强度；
- 极少数病态表达式（如超大幂次、密集奇点）可能因数值发散导致「立即爆炸」，这与原作表现一致。
